# PWM Generator & Frequency Scaler

This directory contains the Verilog modules responsible for clock division and Pulse Width Modulation (PWM) signal generation. In the **MazeSolver Bot (MB)** project, these modules are essential for controlling the speed of the DC motors.

**Team ID:** 2401

## Module Descriptions

This subsystem consists of two primary modules that work in sequence:

1. **`frequency_scaling.v`**: A simple clock divider that takes the 50MHz system clock and scales it down to a more manageable 3.125MHz. This is done to create a slower clock domain for peripherals like the PWM generator.

2. **`pwm_generator.v`**: Takes the 3.125MHz clock and a 4-bit `duty_cycle` value to produce a PWM signal. This signal can be used to drive a motor controller, where the duty cycle directly corresponds to the motor's speed.

The `t1a_fs_pwm_bdf.v` file is a top-level wrapper, likely generated from a Quartus Block Diagram File (.bdf), that instantiates and connects these two modules.

## File Structure

| Filename | Description |
| :--- | :--- |
| `frequency_scaling.v` | Divides the 50MHz input clock by 16 to produce a 3.125MHz output. |
| `pwm_generator.v` | Generates a PWM signal from the 3.125MHz clock based on a 4-bit duty cycle. |
| `t1a_fs_pwm_bdf.v` | Top-level module that connects the frequency scaler and PWM generator. |

## How It Works

### Frequency Scaling

The `frequency_scaling` module uses a 3-bit counter. The output clock (`clk_3125KHz`) is toggled every time this counter rolls over from 7 back to 0. This happens once every 8 cycles of the 50MHz clock. Since a full period requires two toggles (HIGH and LOW), the resulting frequency is:

`50 MHz / (8 * 2) = 50 MHz / 16 = 3.125 MHz`

### PWM Generation

The `pwm_generator` uses a 4-bit counter (`pwm_cnt`) that continuously counts from 0 to 15. This 16-cycle loop forms the period of the PWM signal. The module compares this counter's value to the `duty_cycle` input on every clock cycle:

* If `pwm_cnt < duty_cycle`, the `pwm_signal` is set HIGH.

* Otherwise, the `pwm_signal` is set LOW.

This creates a digital wave where the "on-time" is proportional to the `duty_cycle` value.

* **Duty Cycle %** = (`duty_cycle` / 16) * 100

For example, a `duty_cycle` value of `4'b1000` (8) results in a 50% duty cycle (HIGH for 8 cycles, LOW for 8 cycles).

## Top-Level Interface (`t1a_fs_pwm_bdf`)

| Port | Direction | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk_50M` | Input | 1-bit | The main 50MHz system clock. |
| `duty_cycle` | Input | 4-bit | A value from 0 to 15 that determines the PWM duty cycle. |
| `pwm_signal` | Output | 1-bit | The final PWM output signal. |
| `clk_195KHz` | Output | 1-bit | A secondary clock output, further divided from the 3.125MHz clock. |
| `clk_3125KHz` | Output | 1-bit | The intermediate 3.125MHz clock generated by the frequency scaler. |

## Integration

To control a motor, the `pwm_signal` output is connected to the enable pin of a motor driver IC (like an L293D or L298N). The `duty_cycle` input can be connected to an output register of the RISC-V CPU, allowing the firmware to dynamically set the motor speed by writing values from 0 to 15.
